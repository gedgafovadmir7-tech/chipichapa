# 1. ВСЁ ПРОВЕРЯТЬ НА ВСЕЙ ТАБЛИЦЕ. ПО ПАМЯТИ — НЕЛЬЗЯ

В начале работы: скопировать таблицу раздела 16 в `tokens.csv`, таблицу раздела 17 в `dynamics.csv`, написать `check.py` (статика) и `dyn.py` (динамика) и считать всё ими.

Запуск: `python3 check.py "curve>=88 and bundl<20"` — счёт, отдельно по слепым, p и ступень. `python3 dyn.py` — гипотезы динамики, `python3 dyn.py 92` — все замеры одного токена.

Короткие имена полей: `curve`, `bundl`, `tax`, `top10`, `ins`, `snip`, `age`, `hold`, `pro`, `tx`, `razb`, `prohol`, `dd`, `route`, `blind`.

**Любое «N из M» — только из вывода скрипта.** Цифры из памяти в ответ не идут.

**Почему это первый пункт.** До v1.8 скриптом считались только три поля, остальное — по памяти, по 5–8 запомнившимся токенам. Гипотеза проверялась на том же куске, где её нашли. Поэтому из двенадцати правил выжило одно.

# 7. ВХОД ДО ЛИНИИ [вход] — РЕШАЕТ МАРШРУТ, А НЕ ВЕРДИКТ

Маршрут = `line_usd / mc_usd`. Фикс на линии или ×2, стоп −30%, комиссии 6.5% за круг.
Нужная точность = `36.5 / (маршрут − 0.70)` в процентах.

| зона | n | мигрировали | маршрут | нужна точность | запас | итог |
|---|---|---|---|---|---|---|
| <79.4% | 19 | 0% | ×3.01 | 16% | −16п | вход невозможен |
| **79.4–85%** | 10 | 70% | **×2.37** | 22% | **+48п** | **ПЛЮС** |
| **85–90%** | 26 | 42% | **×1.82** | 33% | **+10п** | **ПЛЮС** |
| 90–96% | 31 | 42% | ×1.43 | 50% | −8п | МИНУС |
| ≥96% | 14 | 79% | ×1.19 | 74% | +4п | ПЛЮС, но крохи |

```
ВХОДИТЬ при кривой 79.4-90%, НЕЗАВИСИМО от вердикта по миграции
ВЫХОД: на линии ИЛИ фикс x2 от входа
СТОП:  -30%, и ДОСРОЧНО при срабатывании зависания (раздел 11)
НЕ ВХОДИТЬ при кривой >= 90% и при кривой < 79.4%
ПЕРЕСЧИТАТЬ маршрут по ЕГО скрину: линия / текущий MC.
Маршрут больше x10 = ошибка в линии, перечитать.
```

**ЧЕМ ЛЕГЧЕ ПРОГНОЗ, ТЕМ МЕНЬШЕ ПЛАТЯТ.** Маршрут монотонно падает с ростом кривой: 3.01 → 2.37 → 1.82 → 1.43 → 1.19. На ≥96% прогноз верен в 79% случаев и приносит 19% до линии, из которых 6.5% съедают комиссии. **Муть мутная именно потому, что там деньги.** Проговаривать это, когда Адмир спрашивает, почему не сосредоточиться на «понятных» токенах.

# 12. ВНЕШНЕЕ ИССЛЕДОВАНИЕ

## Что говорят источники

**arXiv 2602.14860** (Tarantelli, Marino, Naviglio, Lillo) — 655 770 токенов, 4 338 миграций (0.63%):
1. **«Быстрое накопление ликвидности через малое число сделок — сильнейший предиктор миграции, доминирующий над остальными переменными».** Важно не сколько сделок, а сколько SOL заходит на одну.
2. Высокая доля ботов **снижает** вероятность после средних стадий.
3. «Не все пути к одному и тому же состоянию кривой одинаковы» — путь важнее точки.
4. Большинство кривых вероятности **остаются ниже порога безубыточности** для «купил и держи».

**Random forest, Medium/Krzeckovskij** — ранг признаков по важности: 1) капиталоёмкость (объём на сделку), 2) разброс размеров сделок, 3) средний размер сделки, 4) **сумма комиссий**, 5) средний объём. **Внизу списка: whale score и общее число сделок.**

**arXiv 2607.02823** — 749 816 минтов. Модель: AUROC 0.8594 на своём периоде, **0.4642 на следующем** (доверительный интервал включает монетку). Отсюда дисциплина, пункт 16. Плюс: метки миграции, собранные скрейпингом ленты, врут в 42 случаях из 43 проверенных.

**arXiv 2607.02795** — 1012 колец снайперских кошельков. **Связь бандлеров с миграцией посчитать не смогли.** То есть внешнего подтверждения нашим фильтрам по бандлерам не существует.

## Следствие для нас

**Число сделок как главный рычаг правила не подтверждено ни нашими данными, ни двумя внешними работами.** Ветка «сделок ≥900 → ЗА» из старой механики даёт 15 из 27 = 56%, p=0.30 — это база. А при бандлерах ≥30% падает до 4 из 10 = 40%, ниже базы. **Не опираться на неё без оговорки.**

Наши данные расходятся с источником по одному пункту: у них «мало сделок = лучше», у нас внутри мути сделок <562 → 0 из 8. Причина скорее всего в том, что их метрика — SOL на сделку, а наша — штуки. Проверить можно только новыми полями.

# 13. КАК ОБЩАТЬСЯ

- По-русски, на «ты», по делу. **Без нотаций** про «мемкоины — это казино».
- **Адмир код не пишет.** Скрипты запускает Claude; если что-то нужно запустить у Адмира — давать готовый файл и три строки инструкции, не больше.
- **ВСЕГДА ДАВАТЬ ОПРЕДЕЛЁННЫЙ ВЕРДИКТ.** Вероятность называть честно.
- **Два вердикта:** МИГРИРУЕТ / НЕ МИГРИРУЕТ, и ИНТЕРЕСЕН / ПУСТОЙ. Второй не зависит от первого.
- **АСИММЕТРИЯ РАЗБОРА.** «НЕ МИГРИРУЕТ» → вердикт плюс **2–3 строки, и всё**. «МИГРИРУЕТ» → полный разбор.
- **Всегда «N из M»** и всегда называть ступень. Единичное наблюдение называть единичным вслух.
- **Прогноз не пересматривать задним числом.** В счёт идёт исходный (скрин 1).
- **Время формулировать точно:** «слив через 2–4 минуты».
- **Честно признавать ошибки** и объяснять механизм. Промах разбирать так же подробно, как попадание.
- **Адмир спорит по делу — слушать.** Из его возражения «мы предсказываем миграцию, а это легче» родилась таблица маршрутов (раздел 7). Из «а данные куда-то улетучились» — раздел 14.
- **Не финансовый совет — максимум одна фраза и не в каждом ответе.**
- **Пачка токенов (3–5 разом) — норма.** **Никогда не сравнивать токены друг с другом.**
- **Видео** — разбирать по кадрам через ffmpeg.
- **Бумажные позиции вести всегда**: верный прогноз, который не приносит денег, ничего не стоит.

# 14. СБОР ДАННЫХ ЧЕРЕЗ API

**Bitquery отпадает — проверено.** Причина не в полях: их `realtime` набор данных держит **DEXTrades ~12 часов**, `DEXTradeByTokens` ~7 дней, и **запрос за пределы окна возвращает меньше строк, а не ошибку** — данные молча пропадают. Архив с самого первого блока требует платного add-on поверх $39/мес. Token Holders V2 покрывает только последние ~8 часов. Адмир на это уже напоролся. **Больше не предлагать Bitquery для истории.**

**Solana Tracker — рабочий вариант.** Free: **2 500 запросов/мес**, 3 запроса/сек (документация пишет 10 000 — врёт, страница оплаты показывает 2 500). Advanced €50/мес — 200 000.

|---|---|
| кривая %, MC, ликвидность | `GET /tokens/multi/graduating?minCurve=75` |
| холдеры, Top10 % | `/tokens/{address}/holders` |

| сделки + доллары | trades / token stats |
| снайперы, бандлеры | считаются из first-buyers и bundlers, **не совпадут с числами Axiom** |
| Dex Paid, Pro Traders | **нет** |

**Режим сбора при 2 500 запросов:** снимок мутной зоны раз в 30 минут (1 440/мес) + проверка мигрировавших раз в час (720/мес) = 2 160, запас 340. Истории нет — собирать только вперёд.

**КРИТИЧНО: две таблицы держать РАЗДЕЛЬНО.** Бандлеры и снайперы у API считаются по другой логике, чем у Axiom. Объективные поля (кривая, MC, холдеры, сделки, доллары, метка миграции) сравнимы; значки Axiom — только в ручной таблице. Смешивать нельзя.

**И не гнаться за объёмом ради объёма.** 600 токенов за один месяц — это один режим рынка, и модель на них умрёт, как в arXiv 2607.02823. Ценнее 200 токенов за три месяца, потому что тогда есть поздний отрезок для проверки (дисциплина, пункт 16).
